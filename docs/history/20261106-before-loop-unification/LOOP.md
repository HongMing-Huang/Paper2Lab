# Paper2Lab 开发循环

2026-11-05 审查修订。

入口：[产品合同](PLAN.md) · [唯一开发状态](STATE.md)。这是当前执行者遵守的协议，**不是已安装的后台调度器或自动验收服务**。用户提出“开发/继续开发/开始实现”等明确实现请求后在当前会话持续执行；说“暂停/停止”则保存后停。产品里的科研Agent循环另见PLAN §3，两者不能混用：开发者可编辑仓库，产品Agent只调用授权工具。

## 1. 启动、调度与范围

1. 读AGENTS当前入口→STATE→PLAN当前工作包。核对cwd/HEAD/git status，保留已有修改；默认不reset、不换分支、不自动提交。恢复active项前先确认上次执行者已退出，不能抢占同一模块写权。
   首次进入按DEVELOPMENT_PROMPT的导读清单读研究正文/系统合同，并据[代码地图](docs/development/codebase-map.md)核对实际入口、状态和执行分支，在B0.1登记理解与源码差异；不因历史摘要或子Agent读过就声称自己已核实。已有有效理解记录时仅重读受影响部分，不每轮重读整个白皮书。结构整理随真实消费者及对应验收小步推进。
2. 检查新用户输入、已回答问题、失败根因是否变化、已有产物是否仍有效。STATE记录owner（当前chat/执行者）、HEAD与diff身份；无效的旧证据标失效，不全部重跑。
3. 先恢复可推进的active子项，再选解除关键路径的ready子项；同优先级按PLAN顺序。用户明确指定的合法范围优先。一个时刻只写一个子项；独立只读复核可另执行，不并发写生产。
4. 工作包先拆成可独立验收的子项，在STATE写明行为、输入/输出版本、负例、范围、必要命令及完成门。避免一个子项同时重写科学内核、Agent、存储和UI。不为“完整设计”先建无消费者接口。
5. 依赖通常要求done。若工作包只有部分阻塞，可把消费关系细化到已经done的子项产物，必须在STATE明确新依赖、未包含的集成门和理由；不能把未实现功能改名为“可选”来绕过依赖。父项仍未完成，其产品验收仍被阻塞。

任务状态：todo → active → verifying → done；阻塞为blocked，并标记human/environment/dependency/defect/review及questionId或证据。仅文档/类型/fixture通过不等于功能done。PLAN只放合同，STATE只放进度，原始证据按需单独保存，不复制三份tracker。

B0按Node、Python、存储/队列及供应商检查分别记录；任务只需其实际使用的基线。不能把“没配置Qwen”扩大为“所有本地开发都未就绪”，也不能把Node测试通过扩大为Python/供应商已就绪。正式集成验收仍需全部相关门。

跨宿主启动使用根目录[DEVELOPMENT_PROMPT.md](DEVELOPMENT_PROMPT.md)；ZCode实际入口见[启动说明](docs/development/zcode-loop.md)。prompt只负责启动当前协议，不另建状态表；它作为交付文本被审阅时不构成已启动产品开发。当前研究轮的只读范围不自动复制为下一开发轮限制，已授权的本地实现按本节与§5执行。

### 1.1 开工卡与状态汇总

PLAN §4.1给出步骤合同，STATE记录实际执行。开工卡至少写六项：①task.subtask与用户可见行为；②所消费的已验收输入/依赖及版本；③允许修改路径与本次不涉及的工作；④成功、失败和来源/权限负例；⑤确切验证命令、所需环境和资源限额；⑥完成证据与恢复动作。开工卡同时指向PLAN §8的对应白皮书章节、源码函数/类型及版本；直接依赖须实读，来源不可用则使用可验证归档或标未验证，不凭项目名称猜API。信息能从代码确定就自行补，不以填卡为由反复问用户。卡片通过就开始实现，不再另写一份计划。

ready是推导结果，不另存一套状态：依赖产物有效、所需环境可用、无相关未答硬问题、无别的写者且范围已定。基线任务本身允许从缺依赖开始安装/检查；不能要求B0先有自己要建立的测试结果。B0子门按消费者选择，缺Python不禁止已具备Node基线的S1；缺key不阻塞A0.1/.2协议修复。

子项done必须有合同证据和review。父工作包只有全部必要子项与包内集成门通过才done；任何子项active/verifying时父项保持active，只有剩余必要子项均不可执行才标blocked。C1/E1/E2是额外产品集成门，不能按“子项全绿”自动置done。未登记子项默认todo，不能省略它来算完成。

### 1.2 每轮调度步骤

```text
核对最新输入与工作树 → 刷新问题/证据/占用状态
若用户停止：保存检查点并停
若已有变更等待验收：先做可执行验证/独立复核
否则恢复未阻塞的active子项
否则从依赖满足的必要子项选择：明确用户优先项 → 当前检查点关键依赖 → PLAN顺序
冻结开工卡 → 最小实现 → 验证 → 独立复核
通过：保存证据、推进子项、重新计算ready，继续本轮
失败：记录failureId，按失败类型有界修复或阻塞该项，选择独立任务
无ready：只做能产生新证据的必要诊断；仍无则保存并集中报告阻塞
```

“继续独立任务”不能堆叠互相污染的半成品。切换前记录未完成diff、已验证边界与占用路径；新任务若需要改同一接口或消费未验产物，视为有依赖，不开工。可逆的自身失败变更可有选择地撤回或隔离，但保留反例与记录，不执行整个工作树reset。只读review须以冻结范围为对象。

每完成子项或收到新输入就重新调度，避免早先阻塞消失后仍一路做旁支。连续两个子项都未交付可消费产物时，先检查是否拆分过细/接口失控/反复研究；收缩到一个真实消费者，不靠新增文档和空类型制造进度。这是纠偏检查，不是自动停止条件。

## 2. 实现、验证、独立复核

工具与委派：先确认宿主真实能力。主Agent保持唯一生产/STATE写者，可按任务并行启用最多三个只读子Agent做调用链查证、数学/权限专项和独立review；简单任务只保留必要review。每次明确路径/版本/输入/输出/限额，不递归派生；冻结审阅期间主Agent不改被审范围。Explore等角色未必注入AGENTS，派发时显式传约束；通用子Agent需明确限制只读，不能只凭角色名称信任。独立查证可批处理，依赖操作顺序执行。高强度以可消费结果为准，不靠重复扫描/重复测试或工具次数计进度；缺工具只影响相应验收门，不能编造调用与审阅结果。

1. 沿真实调用链确认现状，复用现有内核/端口。行为bug先复现或写独立oracle；缺少来源/错误规则先修合同，再编码。只消除本子项的缺口，不扩张agent.py手写SOP。
2. 最小实现；新增依赖记录版本、许可、被替代的工作、执行位置、生命周期与释放责任。版本升级先有隔离接入证据，不能顺手刷新锁。
3. 跑本子项实际需要的测试，记录命令/退出码、输入、版本、结果和限制。mock测协议，fixture测对应路径；都不替代真实数学、真实Qwen、实际交互。已有失败与本次回归分开；重要门不允许用skip、放宽阈值或“ok或error都行”修绿。
4. 复查diff：无硬编码科学结果、假进度、吞错、第二套数学真值、越权写入、空包、重复executor/Store、废弃入口残留。UI任务执行单浏览器当前路径与Console；HTTP 200、截图、ready绿不代替功能证据。
5. 每开发子项由独立只读reviewer检查diff、合同、依赖和证据，可使用一个子代理，不允许它并发写生产。给reviewer冻结的路径/diff摘要或hash及验收命令；审阅期间不改被审范围。修改后原审阅只对未变部分有效，必须复核增量。审阅结论不冒充测试。无独立review能力则保持verifying/blocked-review，可推进不依赖它的任务；不能自行签“独立通过”。
6. 修复次数按同一未解决失败根因计数：第一次失败立案，此后最多3次有证据的修复尝试；常规成功实现、首次预期红测试不消耗失败额度。每次记录failureId、假设、改变与结果，改名/换对话不清零。到限阻塞该根因，转独立任务；仅修改代码不是新证据。新的外部条件或独立诊断确实推翻原假设后，经只读review确认可再开一组有界尝试，累计历史保留，不能循环重置。
7. 合同、必要检查与独立复核都满足才done。更新STATE并重算ready集合；在授权与会话资源允许时继续下一项，不逐项求确认。每个产品检查点C1/E1/E2另做集成验收，不从子模块测试数推导完成。

## 3. 需要人工时怎样继续

先尝试现有授权内的只读诊断、原文查证或可逆技术选择。真需要人时，问题挂到**最小受影响子项**；传播依赖阻塞，不能把整个产品一律改blocked。

| 情况 | 执行者做什么 | 不回复时怎样处理 |
|---|---|---|
| 可逆实现选择，如函数命名、内部文件位置、等价适配实现 | 自行决定并写理由；有实质偏好再可选询问 | 用符合AGENTS/现有约定的默认值继续；不能人为创建一个审批门 |
| 非必需体验偏好，如提示语气/布局细节 | 给推荐值及影响，问题不阻塞计算主路 | 有合理答复机会后按明示的可逆假设推进（简单偏好通常至少60秒）；答案到来再调整，不能伪称用户批准 |
| 缺科学条件、冲突来源、目标含义不明确 | 先查源；仍不明则创建问题、冻结有关模型/目标分支 | 不填猜测值。可继续别的模型/论文或不依赖该条件的工具工作；明确标注的教学变体需独立修订，不能偷换原模型 |
| 缺凭据、外部服务不可用、缺部署/付费权限 | 检查配置存在性与具体错误，不输出秘密；给安全配置位置/最小所需操作 | 暂停真实服务验收，继续端口、内核、存储、UI等独立任务；fixture明确未证明真实服务；不私自换付费供应商或索要明文密钥 |
| 不可恢复删除、发布、超预算等真实授权门 | 先准备具体diff/产物/验证/回滚，最后再请求必要授权 | 相关动作等待；其他已授权工作继续。沉默、超时和再次说“开发”不自动等于这项单独授权 |

**人工问题记录**写在STATE：questionId、受影响task/subtask、类别与原因、精确问题/选项/推荐、已查证据、当前默认是否允许、可继续任务、回答生效条件（输入revision/HEAD）、提问时间、状态及下次检查触发。记录只包含非敏感配置状态。已有会话授权有效，不重复制造问题。

同一问题无新事实只提一次，优先使用可用的异步提问工具；工具不可用时把问题和影响清楚发给用户，随后继续独立工作。收到的是澄清不是授权时，不扩大解释。状态为open → answered → applied，或superseded；answered仍需验证格式、权限、版本与当前前提，过期回答保留并说明不再适用。

“必须人工”问题不可因超时转默认；若后来补得原文或权限证据，可说明问题为何已消失并标superseded，不能编造用户答复。每完成一个子项检查一次阻塞条件是否有新输入；没有变化不重试网络或付费调用。

无答复时调度顺序：继续当前不依赖问题的子项 → 同工作包独立子项 → 其他ready工作包 → 对现有阻塞做一次能产生新证据的诊断。禁止不断新增装饰功能填时间、无变化重复请求/轮询或长期sleep。状态未变时不重发同一问题；恢复“开发”只检查其条件是否变化。没有后台通知/计时任务就不承诺自动提醒或离线自行恢复。

**只有没有任何可执行的必要工作时，当前会话才因阻塞结束。**此时一次汇总最少的外部动作、受阻目标和已准备好的结果，保存恢复点；不无限等待，也不声称产品已完成。子项失败3轮、缺某个key或一个人工问题都不是全局停止条件。

## 4. 重试、取消和恢复

| 事件 | 处理与恢复条件 |
|---|---|
| 网络/429/暂时进程失败 | 尊重retryAt；同一操作初次失败后至多2次有依据重试。使用同一幂等键，先查是否已有结果；未知是否已计费/提交不能盲重放。到限只阻塞相关任务，不循环换key |
| 输入非法/科学不确定/编译错误 | 不按网络错误重发。保留反例；修改输入/计划/程序时新建修订与语义调用键，重新过门。有限搜索失败不是“无解证明” |
| 执行者被中断/上下文不足 | 保存文件状态、attempt计数、已执行命令/证据、检查点和精确下一动作。下次先核对工作树，复用仍有效证据；不凭摘要声明未跑的命令已过 |
| 用户暂停/取消 | 停止派发新工作；取消本次拥有的子代理/任务并确认其退出。不能终止他人进程；保存仍在运行或外部已提交工作的真实状态 |
| 问题获答/环境恢复 | 每次调度边界优先重新验证，解除最小阻塞并使后继ready；只对受影响revision重验。不能把blocked直接改done，不能用旧回执覆盖新attempt |
| 外部调用结果晚到 | 按invocationId/attemptId/revision核对；过期结果保留可追溯性，不自动应用到当前模型/画布。断线不等于取消，排队不等于执行 |

开发单写者与产品后台队列不同。开发记录里保存的owner用于避免抢写；产品真正的租约/取消/持久恢复必须由J1实现并故障注入验证，不是写进LOOP就已有。

### 4.1 证据失效与接续规则

证据至少绑定受测代码/输入/依赖/运行配置的身份以及真实命令结果。只改说明文字不使无关运行证据失效；接口、schema、数学算法、资源策略或供应商配置改变时，列出受影响的Run/测试/消费者，回到verifying。上游done被推翻时，相关后继加needs_revalidation标记；不得继续发布，但仍可做无关工作。该标记是STATE里的原因，不是另一套进度系统。

会话恢复先读开工卡和最后检查点，核对文件与外部副作用。仍有效的结果直接复用；不确定的调用先查回执，再决定重试。失败日志至少保留输入、实际错误、已经排除的假设和下一验证，禁止只写“继续修复”。已准备但未运行的命令标planned，不能记入passed。

## 5. 授权、完成与仓库质量

本次审查修改计划与实施合同，不启动产品功能实现；以后明确实现请求无需依赖一个特定口令。后续“开发”包含计划内本地编辑、必要依赖、针对性测试及本地服务/单浏览器验收；既有已授权服务按配置和预算使用。未单独授权不push、开Issues/PR、merge、云部署、新增付费服务或运行付费批量生成。不因历史研究阶段限制反复询问本地测试许可；也不把笼统开发口令当外部发布授权。

清理随真实替换发生：查静态/动态引用和注册入口、说明替代者、单独审阅删除并跑对应回归。不丢弃用户未提交工作；研究失败证据先归档/更新索引，不悄悄删。STATE近期记录保留最近5次摘要，原始日志按需放docs/verification/<任务>/<尝试>/并记路径/hash，不把终端全文或凭据灌进状态文件。

基线与验收固定到命令/集合/版本；旧失败若与当前项无关且可复现，登记后允许独立工作继续。任务完成门变更须记录理由、影响和独立复核，不能执行者遇难自行缩小验收。发现done的上游被新事实推翻，将受影响后继标需复验并暂停其发布，仅重跑受影响路径。

每次结束必须留下：当前task/subtask及owner释放情况；HEAD/diff身份；实际变更；命令/结果与证据；review；未验证与人工问题；下一具体动作。给用户报告产品检查点和阻塞影响，不以文档数量、代码量或通过测试数量代替产品完成。

## 6. 用场景检查这个loop是否成立

这些是本协议的**桌面推演，尚不是故障恢复实现或运行测试**：

| 场景 | 应有结果 |
|---|---|
| A2真实Qwen调用发现key未配置，用户暂未回复 | 仅A2真实供应商子项及其依赖等待；已满足依赖的U1/W1/W2/W3继续。A2不因fixture通过变done，待配置后原检查点验收 |
| 一篇ODE论文缺初值 | 先source.read查证；仍缺则等待该模型的回答；其他论文与工具链继续。不能用SIR默认值拼成论文结果 |
| W2死循环负例同根因3次修复失败 | W2标blocked-defect，保留失败输入；切到不依赖VM的W3纯Host/Solver或其他ready项。U2/A3不能绕过W2验收 |
| 用户答案到来时模型已被新版本替换 | 检查question对应revision；旧答案不得直接写新模型，先确认适用范围或标superseded；只重验受影响后继 |
| 已完成开发验收，但发布未授权 | 准备具体发布产物/风险/回滚和一次必要问题；本地成果可交付，不部署、不反复问、不称已上线 |
| 所有剩余关键任务都依赖同一个待答问题 | 保存STATE和最小外部动作，一次说明后结束当前会话；下次输入恢复，不假装后台仍在工作 |
